## Commentary (added when publishing)

Two things stand out in this file, read in hindsight.

**1. The warning was one line above the action.** The manifest documents, in the
same breath, that the ABL is for different hardware and that it is about to be
flashed. The risk was not overlooked; it was accepted. That is a different kind of
mistake than not knowing.

**2. The fallback plan was already written down and was correct.**

```
restore_fastboot = fastboot flash abl_a ... && fastboot flash abl_b ... && fastboot reboot
```

This is the right plan. It requires `fastboot` to work — and `fastboot` is provided
by ABL, which is what the plan is trying to replace. So the fallback depends on the
very component being overwritten.

The `edl_note` line has the same shape: if `fastboot` is dead, use QFIL with the
standalone firehose programmer. That programmer is rejected by this PBL with `0x29`
— which was discovered later, and which is why the EDL route was also dead.

Both fallbacks assumed a capability that did not exist. Neither assumption was
tested before the irreversible operation.
